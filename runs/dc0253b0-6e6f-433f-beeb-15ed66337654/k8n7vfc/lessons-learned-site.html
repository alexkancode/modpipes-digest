Change 1 (v1): curl the play link before asking

likely improves, unconfirmed Stages edited: first-ask, ask.

The defect

The happy run's first question linked to /api/runs/505b…/stages/understand/outputs/game/index.html. That URL lacks /files/ and returns 404. The stress run's first question got the link right.

The edit, exact text added to both prompts

+ Before you ask, run curl -s -o /dev/null -w '%{http_code}' on the link and confirm 200.
+ A 404 means the /files/ segment or the run id is wrong.

Why curl, not the wording, is the fix

The v0 first-ask prompt already gave the exact URL with /files/: "Put the full link in the same text: {{server-url}}/api/runs/<runId>/files/stages/understand/…". The model had the right template and still copied it wrong once. Naming the segment again adds little. Checking the link before sending it does.

Evidence: the same rule, already working in deliver

Counts of tool_use calls whose input contains curl, from each stage's transcript in both test runs:

The sample is small: one failure in six question links. The direction is clear, though. The one stage told to prove its link did so every time.

Lesson for the builder

When one stage proves a link with curl, give every stage that shows a link the same rule.

Change 2 (v2): carry the keep list through the change plan

targets the cause, unconfirmed Edited: the shared change-plan shape in the pipeline prompt, plus ask's inputs and prompt.

The defect

At the stress run's first ask, the user named two keep items: "Stomp, swipe and beam verbs" and "Sound effects". The round-1 ask asked no keep question. It rebuilt the list from the changelog. "Sound effects" disappeared.

FileKeep list
first-ask/outputs/feedback.mdStomp, swipe and beam verbs. Sound effects (the current 18 synth cues).
ask/rounds/1/feedback.mdMint pastel dino art. Mouse-follow walking and the attack buttons. Dino stops off-frame. 60 fps and verify PASS. No sound.

Root cause

  • The ask stage's v0 inputs were merge.game, merge.changelog, verify.verdict and understand.digest. None of them holds the keep list.
  • The validator refuses ask.feedback as an input to ask itself, so the stage cannot read what it wrote last round.
  • Research already reads both first-ask.feedback and ask.feedback. Research is the natural carrier.

The edit

change-plan.md, written by research, one theme per round:
  - the feedback answered, quoted
+ - the keep list, carried whole from the newest feedback file
  ...
ask inputs: + research.change-plan
ask prompt: + Carry the keep list forward. Start from the keep list in change-plan.md.
            + Add what the user names now. Drop an item only when the user releases it.

Why it should work

The round-1 research change plan held no keep section at all. A grep for "keep" finds only sprite constraints. So in v0 the keep list reached nobody after the first ask. With v2 the list rides in the one file that code, art, merge and ask all read.

Lesson for the builder

A loop stage cannot read its own output. Carry its state through an upstream stage in the loop, and name the carried field in the shared shape.
