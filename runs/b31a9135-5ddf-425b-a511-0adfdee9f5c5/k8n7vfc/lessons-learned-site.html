Bottom line

  • No run used v2 or v3. The tester made every edit during or after the two v1 runs, so every change is graded by projecting it onto v1 evidence.
  • v1 already worked end to end. Both runs published the correct version into the correct folder, in one commit of two files, with every coverage check passing.
  • The v3 banner fix and the v2 table-cell rule target real, observed causes, and should help.
  • The v2 critic fix does not reach its stated goal. It removes the stress run's only blocker, but the stress scores were 72 and 74 against a ship bar of 80. Its own "take points off" clause keeps ship false.
  • The largest improvement on offer is not in v2 or v3. Freezing the toolkit would cut about 3 minutes from a 10-minute run and stop per-run code drift.

  • Code-read found all 10 artist-invest-shop routes and all 11 itinerary routes, with guards and the three viz/:technique values. It took 71 s and 103 s.
  • The crawl started and removed a throwaway Postgres container for the happy run. On the stress run, it ran npm ci with placeholder env vars, and left git status clean in both runs.
  • version.mjs picked docs/ over documentation/ and returned v3 after a seeded v2. Publish staged exactly two files in one commit, with no push.
  • All 12 coverage checks passed in both runs: no script, no external URL, no overflow at 390 px, axe clean, size under 5 MB.
  • Round 2 of the stress loop acted on round 1's notes. It folded the phone persona into the visitor, added a plan-maintainer persona with three paths and added participant invite paths. The score rose from 72 to 74.
  • The critic spot-checked three code claims each round, and both handoffs reported the gate truthfully.

The design choice behind most of this: model stages write four JSON files, and script stages render, check and publish them. The loop never writes HTML, so every round renders the same way.

Tester craft

  • The tester ended at 18m38s of a 45-minute budget with v2 and v3 unconfirmed. One fresh stress run takes about 13 minutes, so a confirmation run fit. Next time, start the run as soon as the last version is stored, and write the report while the run goes.
  • The tester wrote straight to modpipes.sqlite runs.definition to retarget a live run. The write bypassed the server and had no effect, because a resumed round never rereads the prompt. Store a version and start a fresh run instead.
  • Good practice worth keeping:
    • The runs used git clones in /tmp/ub-test with symlinked node_modules, instead of an 827 MB cp -a.
    • The tester recovered from the first attempt, which a server restart killed at 19:17Z: it cancelled two dead runs, deleted the stale test copy and removed the leaked container.
    • The tester kept v1.json as the real pipeline, not the test copy, so the version diffs show only real edits.
  • The leaked Postgres container is a pipeline defect, not only housekeeping. A killed crawl never runs docker rm. The crawl's new lesson tells a crawl to sweep containers left by runs that are no longer running.
