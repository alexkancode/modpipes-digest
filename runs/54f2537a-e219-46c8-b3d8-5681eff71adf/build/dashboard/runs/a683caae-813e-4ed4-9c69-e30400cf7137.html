  3. Confirm with the user asked · answered · Fri 6 Nov, 11:35

    Does this match what you want? You start the pipeline with a past run id. It reads that run from ~/.modpipes/runs/<id>: the pipeline definition and prompts in run.json, each stage's wall-clock and token usage in status.json, each stage's context.md, outputs and transcript.jsonl (tool calls with timestamps). For every model stage it judges whether the work splits into two or more independent parallel stages: evidence from the prompt (independent asks), the transcript (tool-call clusters that never read each other's writes), the outputs (independent sections or files) and the timeline (how long each cluster took). It writes one report ranking stages by expected wall-clock saving, each with a verdict, the proposed stages with inputs, outputs and merge, the evidence, and the risks, including the extra context cost of more stages. Then it builds the split pipeline with every endorsed split applied, validates it, and saves it to modpipes as a new pipeline named '<original> (split)'; the original stays untouched. Script stages are reported but never split. If no stage is worth splitting, the report says so and nothing is saved. No comparison run.

    Options: Yes, build that · Yes, with a change

    Yes, build that
