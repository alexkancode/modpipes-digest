Clamping durations removes every negative value

Gather takes "now" once, and a sibling stage that starts later gets a negative live duration. Applied to the two v1 runs.json files, Math.max(0, …) zeroes all three negative values: −218 ms in the happy run and −367 ms and −417 ms in the stress run. No run-level duration was negative. A clamped 0 means "started after the snapshot", which is what the run page already showed after rounding.

Image and video heroes work, but no real run reaches the image path

The tester reported that no run in 3–6 November had an image or video as its primary output. That is true, and the cause is the selection rule, not a lack of data. pickPrimary ranks a starred folder with index.html above a png, as the understanding asks. Seven runs in the period starred a png, and each one also starred an index folder.

  • A fixture runs.json with two hand-set primaries ran through heroes.mjs v2. It rendered an image hero (Pixel loop forge preview.png, 664 ms) and a video hero (Launch video final.mp4, 1,136 ms), with no fallback.
  • For a real video test, period=2026-10-29..2026-10-29 holds three Launch video runs with a present final.mp4.
  • No run in history reaches the image path. The user should decide whether a gallery folder should outrank its own starred png.
  • Pixel art comes out smoothed. Add image-rendering: pixelated for small sources.

How the analysis worked

Replay instead of trust

The tester changed the CSS and the check together and judged both from one smoke run. Replaying the old and new check.mjs against the same old dashboard separated the two fixes. One ablation showed the 300 ms wait does nothing. That took 22 replays and about 4 minutes.

Measure every card

One screenshot shows six cards at one width. measure.mjs reads the box of each card body at 1280 and 390 px. The 390 result reversed the tester's "text no longer collides" verdict for phone width.

Ask why a path never ran

A scan of all 123 run definitions found 29 starred pngs and 4 starred mp4s. Comparing them with pickPrimary showed that the image path is unreachable. A two-run fixture then tested both media paths in one call.

The tester's process

The tester's session took 6 minutes (361 s) of a 45-minute budget, and its two test runs took 63 s and 158 s. The work held up well:

  • The tester treated a passing 15-of-15 check with suspicion and opened the screenshots.
  • The tester reproduced the blank-hero shot by hand (mine-1280.png) before blaming the dashboard.
  • The tester verified v2 offline against the stress data.

Two gaps remain:

  • The tester never checked the 390 view. The check shoots index-390.png, but that shot shows only the page header.
  • Reordering the run-page sample also changed what the link check covers, and nobody looked at that.

The tester's thinking blocks held one non-empty entry. The reasons come from its text blocks.
