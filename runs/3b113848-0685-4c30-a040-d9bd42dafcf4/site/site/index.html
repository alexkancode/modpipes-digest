t1 Rotate the committed live key and replace it with a placeholder

Required to go live · 7 steps

A sk_live_ value is committed in .env.example:1; if real, anyone with the repo can move money.

  1. In the Stripe Dashboard in live mode, open Developers > API keys, find the secret key ending …AbCd, open its overflow menu (⋯) and select View request logs.

    Expect: Workbench opens the request log for that key. No requests means nothing uses it; any requests show which servers you must move to the new key.

    The key is committed at .env.example:1 in commit 801e6c5. Treat it as compromised whatever the logs show.

    https://docs.stripe.com/keys.md#view-request-logs fetched 2026-11-06

  2. On the same API keys page, open the overflow menu (⋯) for the key ending …AbCd, select Rotate key, set Expiration to Now, and click Rotate API key.

    Expect: The old key is revoked and Stripe shows the replacement secret key once. Copy it straight into a password manager or your host's secret store.

    Choose Now unless the request logs showed live traffic. If they did, pick a short expiry and finish step 3 first. Both keys then work for up to 7 days. Never paste the new key into any file in the repo.

    https://docs.stripe.com/keys.md#rolling-keys fetched 2026-11-06

  3. Store the replacement key as STRIPE_SECRET_KEY in your hosting platform's secret store. The repo does not name a host, so use your host's secret command, which prompts for the value.

    npx wrangler secret put STRIPE_SECRET_KEY

    Expect: The host lists STRIPE_SECRET_KEY as a secret, for example in npx wrangler secret list, and the value never appears in the repo.

    The command shown is for Cloudflare Workers. Railway, Fly and Vercel each have their own secrets command. Keys.md recommends a restricted key (rk_live_) over a full secret key.

    https://docs.stripe.com/keys.md#protect-your-keys fetched 2026-11-06

  4. Check that the leaked key is dead. Run one read-only request with it and paste the old key only at the prompt.

    read -rs OLD_KEY && curl -s https://api.stripe.com/v1/balance -u "$OLD_KEY:"; unset OLD_KEY

    Expect: Stripe returns an authentication error, or invalid_request_error if the key was never valid. No balance object is returned.

    If a balance object comes back, the key still works. Go back to step 2 and set Expiration to Now.

    https://docs.stripe.com/keys.md fetched 2026-11-06

  5. Replace the committed value in .env.example with a placeholder that holds no key material.

    sed -i 's/^STRIPE_SECRET_KEY=.*/STRIPE_SECRET_KEY=<sandbox sk_test_ or rk_test_ key, set outside git>/' .env.example

    Expect: Running grep -c sk_live_ .env.example prints 0.

Open risks

Risks the tasks do not cover
  • Hidden billing service. README.md:3 may describe billing that runs outside this repo. If a live account already has customers and subscriptions, building t4 to t7 could charge customers twice. Run t2 and check stripe subscriptions list --live before building anything.
  • Key in git history. Rotating the key (t1) does not remove the value from commit 801e6c5. Any clone or fork still holds it, so treat the old key as permanently exposed.
  • Unknown host. No deploy config exists (no wrangler.toml, Dockerfile or CI), so we cannot check production secrets. The webhook raw-body handling depends on the runtime (constructEventAsync on Workers).
  • Tax, receipts and invoicing. The app is an invoicing app, but local invoices (src/app.js:2) are not tied to Stripe invoices. Sales tax and Stripe-hosted invoicing are out of scope here (unverified).
  • API version drift. A future SDK upgrade crosses majors listed in facts.json, such as the billing_cycle_anchor change in 2026-09-30.endive.
